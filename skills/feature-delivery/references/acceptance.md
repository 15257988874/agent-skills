# 验证与交付

## 默认执行

读取项目允许的验证方式，运行与改动有关的最小检查。默认用项目开发环境检查真实页面及接口；优先复用现有服务，必要时按项目既有命令启动开发服务并记录地址。

项目没有限制时可以运行适用的类型检查和生产构建；用户或项目明确禁止时遵守限制，报告未运行及原因。没有相关脚本就说明不存在，不能把未运行记成通过。检查脚本实际内容后执行，避免间接触发禁止命令。

使用当前开发助手可用的浏览器能力。缺少浏览器工具时说明情况，引导用户配置或明确选择手动验证，不能用静态截图和 Mock 代替。适用的专用工具规范先读取。

## 真实验收

| 维度 | 根据本次功能验证 |
| --- | --- |
| 产品行为 | 入口、操作、跳转、筛选/分页、表单校验、权限与状态变化 |
| UI | 对照指定节点/画板的真实截图，检查布局、字体、颜色、素材及有关状态 |
| API | 请求方法/路径/参数、字段转换、分页、鉴权、真实响应及错误反馈 |
| 通用状态 | 加载、空数据、失败及防重复操作等适用状态是否按项目约定工作 |
| 回归 | 被改动的共享组件或相邻流程是否受影响 |

接口联调在用户放入范围的开发/测试环境执行。联调需要的数据写入、删除等操作先确认目标环境与可用测试数据；不能把生产数据修改隐含在普通验证中。没有确认适用业务权限时不能执行操作。

## 验证受阻

页面要求登录、Cookie 失效、账号/权限不足、测试环境不可达：更新为 `awaiting_access`，告诉用户阻碍和具体未验证项，请用户登录/授权或提供环境；也可以询问是否跳过这些项，由用户手动验证。

必须收到用户明确选择后再跳过。用户暂时离开、等待超时、Mock 通过、代码看似正确，都不能当作跳过同意。暂停在受阻验证点，不以完成代码为由宣布本次任务已交付。

用户选择手动验证后，记录答复，交付状态为 `delivered_with_unverified_items`。逐项提供环境/路由、前置条件、操作步骤、期望界面和请求结果，说明实际未验证内容。

## 失败归因

对照任务开始时的工作区记录、本次 diff 和可用基线证据判断失败：

- 本次引入：在本次范围内修复并重新验证相关项。
- 已有问题：列出证据及影响，不顺手改无关文件；修复需扩大范围时问用户。
- 归因不明：说明证据不足并继续最小诊断，不能因报错文件未修改就宣称是旧问题。

不能通过删除既有测试、改快照或吞掉错误来获得通过结果。

## 交付记录

逐功能报告已实现内容、文件与原因、实际检查、浏览器及联调证据、失败/未验证项和用户决定。区分“格式有效”“代码已实现”“Mock 通过”“真实交互已验证”“视觉已核对”“接口已联调”；有未决验证时不笼统宣称全部完成。

更新用户指定目录下的本次记录，保留来源版本/读取时间及手动验收步骤。不要覆盖前次迭代记录。

## Skill 维护时的行为评测

以下场景用于维护此 Skill，采用脱敏资料和隔离环境。决策评测不等同于真实平台连接或产品端到端验收。

| 场景 | 合格行为 |
| --- | --- |
| 链接包含整版，但用户只加一个筛选 | 只实施用户描述范围 |
| 编辑冲突，导出完整，交付时间紧 | 暂停整个任务并询问，不继续导出或编辑骨架 |
| 只有原型截图、没有交互注释 | 标记读取不完整，补读或询问 |
| 缺少权限和删除恢复规则 | 暂停并询问；加载/空数据/错误默认复用 |
| 原型灰框，UI 颜色完整 | 按原型功能和 UI 样式实施，不误判纯视觉冲突 |
| Mock 成功、真实页面需登录 | 引导登录/授权或请求明确手动验收选择 |
| CI 报未修改的旧文件 | 查基线和 diff，证据不足则归因不明 |
| 首次无记录设置 | 先问目录并持久化，再实施；后续沿用 |
| Vue 项目、设计工具给 React 代码 | 保持项目技术栈和组件体系 |
| 项目禁止构建 | 遵守禁令并报告未运行 |
| 新空目录要求搭建 | 说明第一版边界，询问后续处理 |
